# Customer-authorised Hub Help support ingress

Development only; disabled by default. Companion Hub branch `feat/customer-help-tickets-20261106` adds a reviewed customer submission form. Any active Hub customer can send an issue to the fixed V79 support account without a Tiquet subscription. This endpoint does not provide customer access to the V79 tenant, reuse Sentinel permissions or change paid entitlements.

`POST /api/integrations/hub-help/v1/tickets` accepts strict version-1 signed JSON from `v79-hub-help`; raw-body SHA256/HMAC with millisecond timestamp and five-minute skew. Browser credentials/Origin, invalid signatures, destination/priority overrides and unbounded input fail closed. Use private network/TLS, dedicated secret and no redirects.

Configure `V79_HELP_SUPPORT_ENABLED=1`, matching dedicated `V79_HELP_SUPPORT_SHARED_SECRET` of at least 48 bytes, explicit V79 `V79_HELP_SUPPORT_ACCOUNT_ID` and `V79_HELP_SUPPORT_ORGANIZATION_ID`, plus Neil's `V79_HELP_SUPPORT_OWNER_USER_ID` and `V79_HELP_SUPPORT_OWNER_HUB_USER_ID`. All linkage is rechecked against the active account and current Admin row on every delivery, including replay. Missing configuration leaves this endpoint unavailable. No actual mapping/secret was set in this phase.

Creates a request-stage ticket with priority `high`, assigned to the configured Admin's current name, requester email on the ticket, App Help tag, audit entry and an in-app notification to that Admin's ID. Receipt and all records commit in one transaction. No portal token, email, client auto-creation, payment or product event is emitted. Guide outcomes are customer claims, not machine-verified facts.

A PostgreSQL advisory lock serialises each requester. Semantic hashes reject conflicting replays; persistent receipts survive service restarts and ticket deletion. Deleted jobs return 410 and are not resurrected. Keep `hub_help_support_receipts` in encrypted DB backups and through rollback. It has no automatic retention expiry; deleting it can re-enable old delivery. Secret rotation changes Hub-derived IDs and needs a retry migration plan. Limits: eight active requests, five new tickets/hour and ten/day per requester; duplicate receipts bypass creation quota.

Based on deployed security branch `release/tiquet-p1-session-file-security-20261102` / `9020030`; do not replace it with older main. Additive schema/table only. Release alongside the reviewed Hub feedback/ticket dependencies; preserve current images, config and database backup. No deployment or production test ticket has been performed.

Validation: three local config/schema/default-off HTTP tests passed, TypeScript/build passed, and an actual disposable Hub → Tiquet child process → PostgreSQL 17 integration passed from the Hub companion branch. It covered response lost after commit, concurrent duplicate delivery, both process restarts, owner/account linkage, signed/auth boundaries, fixed High priority, single notification and atomic rollback. Durable hourly limit tested; separate 24-hour boundary/load/independent penetration tests not claimed. Hub documentation contains detailed evidence and the explicit integration command.
